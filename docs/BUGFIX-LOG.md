## BUG-20261028-001：管理员姓名、欢迎语与文字头像显示不符合要求

- **记录日期**：2026-10-28
- **模块**：工作台、顶部用户信息、个人中心及参保人文字头像
- **状态**：已修复，页面检查与前端构建通过

### 问题表现

管理员姓名显示为“林管理员”，工作台显示“下午好，林管理员。欢迎回到安澜医保。”；顶部头像显示姓名末两字“理员”，没有按姓名首字显示。

### 原因

演示管理员初始化姓名为“林管理员”；顶部与个人中心通过 `slice(-2)` 取姓名末两字，参保人头像通过 `slice(-1)` 取末字；工作台使用旧欢迎文案。

### 修复内容

1. 将初始化管理员姓名及当前本机 MySQL 中 `admin` 的显示姓名更新为“金管理员”。
2. 将欢迎文案改为“欢迎来到安澜医保。”，保留根据时间显示早上、下午、晚上问候的逻辑。
3. 顶部、个人中心、参保档案列表与详情、工作台近期记录、新建就诊中的文字头像统一使用去除首尾空白后的姓名第一个字；顶部姓名为空时显示“安”。

涉及文件：`backend/src/main/java/com/example/insurance/DemoData.java`、`frontend/src/App.vue`、`frontend/src/views/Dashboard.vue`、`Profile.vue`、`Patients.vue`、`VisitCreate.vue`。

### 验证结果

- 当前本机数据库查询确认 `admin` 显示姓名为“金管理员”。
- 浏览器刷新后，工作台实际显示“下午好，金管理员。欢迎来到安澜医保。”，顶部头像显示“金”；个人中心同样显示“金”和“金管理员”。
- 浏览器参保档案中的文字头像显示姓名首字，例如“郭春燕”显示“郭”。
- 前端 `npm run build` 的 TypeScript 检查与 Vite 生产构建通过。

## BUG-20261028-002：组织名称查询不筛选，搜索提示包含不存在的编码字段

- **记录日期**：2026-10-28
- **模块**：系统管理 → 组织管理
- **状态**：已修复，自动化验证与构建通过；用户页面复测待反馈

### 复现步骤与问题表现

1. 使用管理员账号进入“组织管理”。
2. 在搜索框输入“惠民保险服务公司”，点击“查询”。
3. 页面仍显示全部组织，没有按名称筛选；搜索提示写着“搜索组织名称或编码”，但组织模型、表格和表单均没有编码字段。

预期：只显示名称匹配的组织；搜索提示与实际支持的字段一致。

### 原因

前端已经传递 `keyword`，但后端 `GET /api/admin/orgs` 没有接收、使用搜索词，始终返回全部组织。搜索框还复用了通用资源页面的“名称或编码”提示。

此外，原页面使用当前表格结果查找上级组织和生成上级选项。若直接增加后端筛选，上级组织可能不在搜索结果中，导致错误显示“无上级”或编辑选项缺失，因此修复时一并处理。

### 修复内容

1. 后端接收可选 `keyword`，按组织名称包含匹配，去除搜索词首尾空白；未填写或仅有空白时返回全部组织，保留权限校验和 ID 升序。
2. 组织管理搜索提示改为“搜索组织名称”，没有新增编码字段。
3. 分别保存查询结果和完整组织选项，确保筛选后上级名称及编辑选项仍正确；菜单管理继续使用其自身的上级菜单选项。
4. 更新 OpenAPI 描述和接口约定，新增组织查询回归测试。

涉及文件：`backend/src/main/java/com/example/insurance/AdminController.java`、`backend/src/test/java/com/example/insurance/OrganizationSearchTest.java`、`frontend/src/resourceSchemas.ts`、`frontend/src/views/ResourcePage.vue`、`docs/API-CONTRACT.md`。

### 验证结果与复测范围

- `OrganizationSearchTest` 共 **4 项通过，0 失败、0 错误、0 跳过**，覆盖完整名称、部分名称、首尾空白、未提供搜索词、空白搜索、无匹配结果、医生无权限及匿名访问。
- 回归测试使用独立 H2，未写入本机 MySQL。
- 前端 TypeScript 检查、Vite 生产构建与后端打包通过；更新后的前后端服务已启动。
- 运行中的 OpenAPI 已包含组织查询的 `keyword` 参数；前端入口与后端文档接口均返回 HTTP 200。
- 用户选择自行登录验证页面，本轮未代填验证码、保存或删除组织。页面复测结果尚待用户反馈。

用户复测：刷新“组织管理”，搜索“惠民保险服务公司”应仅显示该公司；搜索“惠民”应显示名称包含该词的组织；搜索不存在的名称应显示空结果；点击“重置”应恢复全部组织。筛选后检查该公司的上级仍为“市医保服务中心”，打开编辑弹窗应保留完整上级组织选项，查看后取消即可。

## BUG-20261028-003：中文首次查询与重复操作时的查询结果不稳定

- **记录日期**：2026-10-28
- **模块**：就诊登记、保险审核、参保档案、保险方案、手术档案、资金流水、用户管理、组织管理、数据字典、菜单管理、操作日志、文件中心
- **状态**：修复已完成并部署；后续页面测试由用户自行进行

### 问题表现

用户在保险审核的“审核拒绝”页输入“王志远”，第一次点击“查询”没有得到预期结果，多次操作后才成功；其他模块存在相似的间歇查询问题。

### 排查确认的共性问题

1. Element Plus 2.14.7 在中文组合输入期间不立即提交 `v-model`，组合结束后通过 `nextTick` 同步。原页面直接读取模型并通过 `keyup.enter` 查询，存在读取旧关键词、把确认中文候选的回车当成搜索的风险。
2. 原列表加载没有请求顺序保护，较早发出的慢请求可以覆盖后一次查询结果，旧请求也可能提前关闭新请求的加载状态或显示过期错误。
3. 多数后端查询没有统一去除关键词、类型和状态的首尾空白；菜单配置接口还直接忽略 `keyword`。

就诊接口原有的关键词与审核状态组合、医生本人数据范围正确；未发现必然导致首次失败的后端条件分组问题。上述风险不能单凭静态分析认定为用户该次故障的唯一原因。

### 修复内容

1. 新增统一 `SearchInput`，在查询按钮和状态切换的查询边界读取输入框当前文字，去除首尾空白；回车使用 `keydown` 并识别组合输入和 `229` 键码，确认中文候选时不误提交查询。
2. 清空操作等待输入同步后查询空词；重置先清除模型后直接加载，避免重新读回旧文字。
3. 新增 `useLatestQuery`，仅最后发起的请求可更新结果、分页、错误提示和加载状态；页面卸载后使未完成请求失效。
4. 将参保、就诊/审核、流水、通用资源维护、日志和文件页接入统一查询保护。文件页继续实时过滤，关键词变化时回第一页，刷新后校正页码。
5. 后端统一搜索词及相关筛选值的首尾空白处理；菜单管理新增名称、路径和权限代码的真实筛选，继续保留权限校验与医生数据范围。
6. 组织与菜单的完整上级选项分别保存，筛选结果不会清空上级名称或编辑选项；各模块搜索提示与实际支持字段一致。
